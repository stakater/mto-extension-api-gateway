# Gateway baseline — what the platform gives a tenant API gateway, and where it stops

**Versions:** Red Hat OpenShift Service Mesh **3.4** (Istio 1.30, Envoy 1.38,
GA 2026-07-09), Gateway API **v1.5.1**, Red Hat Connectivity Link **1.4.x**
(upstream kuadrant-operator v1.6.0, Authorino v0.26.4, wasm-shim v0.15.0,
limitador-operator v0.18.5), Template Operator **v2**, read on 2026-11-16.
Upstream facts were read in the tagged source on GitHub; Istio pages describe
the latest Istio, newer than the 1.30 that Service Mesh 3.4 ships.

Every design decision cites a row here. **VERIFY** marks what the docs did not
settle; each is a task in story G.0 (`docs/planning/G0-live-spike.md`). When a
product changes, update this file first.

## 1. Service Mesh and Istio

| # | Fact | Consequence | Source |
|---|---|---|---|
| M1 | Service Mesh 3.4 is based on Istio 1.30 and supports OpenShift 4.20 and later. Ambient mode (ztunnel, waypoints) is GA since Service Mesh 3.2; multicluster ambient is still Technology Preview. | Ambient is a supported base for the backend lock. One cluster per tenant gateway; multicluster is out of scope. | [Service Mesh 3.4 announcement](https://www.redhat.com/en/blog/introducing-red-hat-openshift-service-mesh-34); [3.4 version tables](https://docs.redhat.com/fr/documentation/red_hat_openshift_service_mesh/3.4/html/release_notes/ossm-release-notes-version-support-tables) |
| M2 | `EnvoyFilter` is Developer Preview: available but not supported, except where documented. Its patches are "very sensitive to the format of the Envoy configuration generated by Istio" and can break when that format changes; Red Hat may ask to reproduce a problem without it. Service Mesh 3.4 adds `TrafficExtension` (Technology Preview), which replaces `WasmPlugin`. | No `EnvoyFilter`, `WasmPlugin` or `TrafficExtension` in our rendered output (ADR-0003). **VERIFY** the 3.4 support table still lists `EnvoyFilter` as Developer Preview. | [Service Mesh 3.2 release notes](https://docs.redhat.com/en/documentation/red_hat_openshift_service_mesh/3.2/html-single/release_notes/index); [3.3 feature support tables](https://docs.redhat.com/en/documentation/red_hat_openshift_service_mesh/3.3/html/release_notes/ossm-release-notes-feature-support-tables) |
| M3 | For a Gateway API `Gateway`, Istio deploys a Deployment, Service and ServiceAccount named `<Gateway name>-<GatewayClass name>`. `spec.infrastructure.parametersRef` names a ConfigMap in the Gateway's namespace whose keys `deployment`, `service`, `serviceAccount`, `horizontalPodAutoscaler` and `podDisruptionBudget` are strategic-merge patches. No HPA or PDB is created by default. | One ConfigMap per tenant gateway gives autoscaling and a disruption budget (ADR-0002). Object names carry the class name (design §6). **VERIFY** that Service Mesh 3.4 honours `parametersRef`, and the default replica count. | [Istio: Gateway API](https://istio.io/latest/docs/tasks/traffic-management/ingress/gateway-api/) |
| M4 | In ambient mode, ztunnel carries pod-to-pod traffic over mTLS (HBONE) with each workload's identity, and enforces L4 `AuthorizationPolicy` rules (source principals, namespaces, ports) without a waypoint; L7 rules need a waypoint. `istio.io/use-waypoint` binds a namespace, Service or pod to a waypoint; ingress traffic skips the destination waypoint unless `istio.io/ingress-use-waypoint=true`. | The backend lock is an L4 rule on source principals, enforced by ztunnel (ADR-0007). **VERIFY** that a gateway of class `istio` reaches an ambient backend over HBONE, so its identity is checked. | [Istio: L4 policy in ambient](https://istio.io/latest/docs/ambient/usage/l4-policy/); [Istio: waypoints](https://istio.io/latest/docs/ambient/usage/waypoint/); [Istio: ambient data plane](https://istio.io/latest/docs/ambient/architecture/data-plane/) |
| M5 | With discovery selectors in the mesh configuration, istiod ignores namespaces whose labels don't match (for example `istio-discovery=enabled`). | A route's namespace outside the mesh breaks the backend lock silently; the extension reports it (design §7). Namespace labels come from the `Tenant`, not from this extension. | [Istio: discovery selectors](https://istio.io/latest/docs/reference/config/istio.mesh.v1alpha1/#MeshConfig) |
| M6 | `AuthorizationPolicy` and `RequestAuthentication` accept `targetRefs`; a Gateway API `Gateway` target must be in the policy's namespace. A policy sets `selector` or `targetRefs`, not both. | The Istio-native fallback (ADR-0003, alternatives) is possible; the backend lock uses `selector`. | [Istio: AuthorizationPolicy](https://istio.io/latest/docs/reference/config/security/authorization-policy/); [Istio: RequestAuthentication](https://istio.io/latest/docs/reference/config/security/request_authentication/) |
| M7 | `RequestAuthentication` `outputClaimToHeaders`: "The header will be overridden if it already exists in the request." Only string, int and bool claims. | The fallback could replace `x-sub`, but not a list claim such as `allowed_apis` in `x-roles`. | [Istio: RequestAuthentication](https://istio.io/latest/docs/reference/config/security/request_authentication/) |

## 2. Gateway API

| # | Fact | Consequence | Source |
|---|---|---|---|
| A1 | A listener's `allowedRoutes.namespaces.from` is `All`, `Same` (default) or `Selector`; with `Selector`, only routes in namespaces matching the label selector attach (Core). Attachment needs both sides: the route's `parentRef` and the listener's permission. | The tenant label is the listener's selector: a route from another tenant's namespace never attaches (ADR-0002). | [gateway_types.go v1.5.1](https://github.com/kubernetes-sigs/gateway-api/blob/v1.5.1/apis/v1/gateway_types.go); [Cross-namespace routing](https://gateway-api.sigs.k8s.io/guides/multiple-ns/) |
| A2 | A `parentRef` to a Gateway in another namespace is governed by `allowedRoutes`, not by a `ReferenceGrant`. A `backendRef` needs a `ReferenceGrant` only when it names another namespace. | Route and backend in one namespace: no `ReferenceGrant` (ADR-0005). | [shared_types.go v1.5.1](https://github.com/kubernetes-sigs/gateway-api/blob/v1.5.1/apis/v1/shared_types.go) |
| A3 | A listener with a `hostname` accepts only routes whose hostnames intersect it; a wildcard listener hostname matches subdomains. | Hostname ownership per tenant comes from the listener (ADR-0009). **VERIFY** how many labels `*.<tenant>.<base>` matches on Service Mesh 3.4. | [gateway_types.go v1.5.1](https://github.com/kubernetes-sigs/gateway-api/blob/v1.5.1/apis/v1/gateway_types.go) |
| A4 | `RequestHeaderModifier` (add, set, remove) on a route rule is Core; `URLRewrite` with `ReplacePrefixMatch` is Extended; one `URLRewrite` per rule. | Path rewrite and header filters stay in the team's `HTTPRoute`. Service Mesh supports both (G.0 confirms `URLRewrite`). | [httproute_types.go v1.5.1](https://github.com/kubernetes-sigs/gateway-api/blob/v1.5.1/apis/v1/httproute_types.go) |
| A5 | In policy attachment, `sectionName` names a Gateway listener or an HTTPRoute rule; a policy whose section doesn't exist must fail to attach. | The default deny targets the tenant listener by `sectionName` (design §3.1). | [policy_types.go v1.5.1](https://github.com/kubernetes-sigs/gateway-api/blob/v1.5.1/apis/v1/policy_types.go) |

## 3. Connectivity Link (Kuadrant)

| # | Fact | Consequence | Source |
|---|---|---|---|
| K1 | Connectivity Link 1.4 is supported on OpenShift 4.19–4.22 with Service Mesh 3.4 as the Gateway API provider. 1.4.0 is deprecated (authentication failures, gateway instability); use 1.4.1 or later. A 1.5 documentation set exists. On OpenShift 4.19 and later, the Ingress Operator can provide the Service Mesh for a GatewayClass with controller `openshift.io/gateway-controller/v1` (`openshift-default`). | Prerequisite with a minimum of 1.4.1. The GatewayClass name is a bootstrap value (`istio` or `openshift-default`). **VERIFY** the 1.5 support matrix before G.0. | [Supported configurations](https://access.redhat.com/articles/7092611); [1.4 release notes](https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.4/html/release_notes/index); [Installing on OpenShift](https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.1/html/installing_connectivity_link_on_openshift/install-prerequisites_connectivity-link) |
| K2 | `AuthPolicy` authenticates JWTs with `rules.authentication.<name>.jwt.issuerUrl`; Authorino uses OIDC discovery and the issuer's JWKS. Red Hat lists RHBK as a supported identity provider. | RHBK stays the token issuer; the issuer URL is a bootstrap value. | [authpolicy.md v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/doc/reference/authpolicy.md); [Authorino features v0.26.4](https://github.com/Kuadrant/authorino/blob/v0.26.4/docs/features.md) |
| K3 | Authorization uses `authorization.<name>.patternMatching.patterns`; each pattern is a CEL `predicate` or a selector/operator/value with `eq`, `neq`, `incl`, `excl` (exact value in an array) or `matches` (regex). JSON-path selectors are deprecated in favour of CEL. | `incl` can't express "starts with `api.team-a.orders.`"; the rule is a CEL `exists()` predicate on the claim list (design §5). **VERIFY** the predicate on a real token. | [Authorino features v0.26.4](https://github.com/Kuadrant/authorino/blob/v0.26.4/docs/features.md) |
| K4 | `response.success.headers` are injected into the request and **replace** a header of the same name (the wasm-shim applies a Set; its test replaces a client's `authorization` header). | Caller-sent `x-sub` and `x-roles` never reach the backend, with no strip filter. **VERIFY** on the wasm-shim that Connectivity Link 1.4.x ships. | [wasm-shim auth tests v0.15.0](https://github.com/Kuadrant/wasm-shim/blob/v0.15.0/crates/wasm-shim/tests/auth.rs); [headers task](https://github.com/Kuadrant/wasm-shim/blob/v0.15.0/crates/kuadrant-filter/src/kuadrant/pipeline/tasks/headers.rs) |
| K5 | A `RateLimitPolicy` limit has `rates[{limit, window}]`, `counters[{expression}]` (CEL) and `when[{predicate}]` (CEL, all true). Limitador stores counters: in memory (default, not shared), Redis, Redis cached, or disk. | Tiers are limits selected by a claim predicate and counted per caller (design §3.1). Counter storage for several Limitador replicas is a platform choice (Q12). | [ratelimitpolicy.md v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/doc/reference/ratelimitpolicy.md); [Limitador storage](https://github.com/Kuadrant/limitador-operator/blob/v0.18.5/doc/storage.md) |
| K6 | A policy's rules are bare, `defaults` or `overrides` (mutually exclusive). Defaults apply until a more specific policy replaces them; overrides "cannot be weakened by route-level policies". `strategy` is `atomic` (default: the whole policy wins) or `merge` (same-named rules replaced, others kept). Hierarchy: Gateway → listener → route → rule. | The baseline is a Gateway-level `overrides` with `strategy: merge`, so route-level rules survive; the default deny is a separate listener-level `defaults` (ADR-0004). **VERIFY** the composition (Q3). | [Auth overview v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/doc/overviews/auth.md); [authpolicy_types.go v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/api/v1/authpolicy_types.go) |
| K7 | On Istio, the Kuadrant operator itself creates an `EnvoyFilter` per gateway (in the gateway's namespace) to load its wasm filter, plus `EnvoyFilter`s for the auth, rate-limit and tracing clusters. | Those are the product's own, managed and upgraded with Connectivity Link; ours are none (ADR-0003). Admission must not refuse them in the gateway namespace (ADR-0008). | [istio_extension_reconciler.go v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/internal/controller/istio_extension_reconciler.go) |
| K8 | A policy's `targetRef` can only name an object in the policy's namespace; allowed kinds are `HTTPRoute`, `GRPCRoute` and `Gateway`. | Gateway-level policies live in the gateway namespace; route-level ones in the route's namespace. | [authpolicy.md v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/doc/reference/authpolicy.md); [ratelimitpolicy.md v1.6.0](https://github.com/Kuadrant/kuadrant-operator/blob/v1.6.0/doc/reference/ratelimitpolicy.md) |
| K9 | We found no source that says which Red Hat subscription includes Connectivity Link. | A platform team checks its subscription before G.0. Never a price in these docs. | — (not found) |

## 4. Template Operator and the Multi-Tenant Operator

| # | Fact | Consequence | Source |
|---|---|---|---|
| T1 | The Multi-Tenant Operator labels every tenant namespace `stakater.com/tenant: <tenant>`. | The listener selector and the child render's namespace scope both key on it. | [mto-extension-vault-enterprise charts README](https://github.com/stakater/mto-extension-vault-enterprise/blob/main/charts/README.md) |
| T2 | Template Operator v2 has two kinds, `Template` and `TemplateInstance`. A parent `TemplateInstance` can emit one child `TemplateInstance` per `Tenant`; a child's parameters can be the list of objects of a kind in the namespaces its `namespaceSelector` matches (`objectFieldRef`). Child `namespaceSelector` needs v0.0.5 or later. There is no `TemplateGroupInstance` in v2. | The bootstrap chart fans out per tenant; the child gets the tenant's `HTTPRoute`s and `Service`s as lists (design §2). **VERIFY** list parameters for `HTTPRoute` (Q6). | [mto-extension-vault-enterprise charts README](https://github.com/stakater/mto-extension-vault-enterprise/blob/main/charts/README.md); [Template Operator parameters](https://github.com/stakater/template-operator-v2-docs/blob/main/content/concepts/parameters.md); [Template Operator API](https://github.com/stakater/template-operator-v2-docs/blob/main/content/reference/api.md) |
| T3 | A `Template`'s `sync.mode` is `off` (default: no drift revert; frozen after the first clean apply), `revert` (drift reverted) or `strict` (drift reverted, and the admission webhook refuses edits to rendered objects). | Our Templates use `revert`, or upgrades and new routes would never reach a tenant (ADR-0001); G.1 decides whether the gateway-level baseline uses `strict`. | [Template Operator sync](https://github.com/stakater/template-operator-v2-docs/blob/main/content/concepts/sync.md) |
| T4 | Template Operator deletes only objects it applied itself (ownership by provenance), and renders strictly: a missing value fails the render. | Offboarding removes our objects and never another tenant's or a hand-made one. | [Template Operator lifecycle](https://github.com/stakater/template-operator-v2-docs/blob/main/content/concepts/lifecycle.md); [orphan handling](https://github.com/stakater/template-operator-v2-docs/blob/main/content/how-to-guides/orphan-resource-handling.md) |
| T5 | Whoever can set `stakater.com/tenant: X` on a namespace gets tenant X's access through the extensions. | Only the Multi-Tenant Operator and cluster admins may set the label (as for the Vault extensions). | [mto-extension-vault-enterprise charts README](https://github.com/stakater/mto-extension-vault-enterprise/blob/main/charts/README.md) |

| Q11 | Is Envoy's `x-request-id` enough for request correlation, or do APIs need another header, and from where? | ADR-0003 |
| Q12 | How many Limitador replicas, and with which counter storage, keep limits exact across gateway pods? | design §3.1, AC-RL-1 |
